# AI 开发笔记

这篇文档记录修改本项目时容易踩到、但从代码里不一定一眼看出的问题。面向 AI 助手。

## 顺序约束

- 所有对 USD 的修改、材质采集、名字表采集，都必须在调用 Newton 的 USD 导入之前完成。导入过程会改写 stage，之后拿到的旧 prim 句柄会失效。
- MJCF 后处理的顺序不能随意调整。碰撞掩码修复必须在视觉与碰撞分组之前；名字还原必须在接触排除和标记点之前；几何统一命名必须在掩码修复、视觉与碰撞分组和补丁之后，且不能早于材质匹配（材质是按旧名字匹配的）；网格外置必须在写出文件之前。
- 需要在 USD 上新增或修改属性时，优先写成独立函数，由流程编排处调用，不要在解析函数内部临时修改。

## USD 与 Newton 的行为

- 读取 USD 属性时，资产里写好的值优先于调用方传入的默认值。想覆盖资产里的设置，必须改 USD，不能只传参数。凸包顶点上限就是典型例子：只传导入参数时，资产里的值仍然生效。
- 遍历 stage 时必须能走到实例代理，否则会漏掉放在可实例化容器里的视觉几何和材质。
- `physics:collisionEnabled = false` 在 PhysX 里表示碰撞过滤，在 MJCF 里等于没有碰撞体。重新打开后需要自行补接触排除。
- 碰撞体自己带材质信息时，Newton 会把它当成材质定义并跳过整个碰撞形状。修复方式是把材质信息拆到单独的 prim。
- 资产关闭整机自碰撞时，导出的碰撞掩码可能全部为 0。判断一个几何是否真的是碰撞体，应该对照 Newton 模型里带碰撞标志的形状，而不是只看 MJCF。
- 所有碰撞网格最终都会经过凸包编译，MuJoCo 只接受凸的碰撞网格。缺少网格近似依赖时，凸包会退化成包围盒，而且没有明显报错。
- 凸包顶点数有默认上限，超出部分会被截断，截断后的形状可能不对称。需要更高精度时同时修改 USD 属性和导入参数。
- Newton 的 MJCF 写出接口不会设置时间步长，不补就会退回 MuJoCo 默认值。
- 写出接口会把由数组构造的网格写成内联顶点和面片，视觉网格多时 XML 会非常大，需要外置。
- 材质信息不会随写出接口一起导出，必须在解析之前单独采集。

## MJCF 文本处理

- 元素查找要注意作用域。`<equality>` 下的 `<joint>` 和运动学 `<joint>` 同名，`<default>` 下的 `<geom>` 也是几何模板。直接遍历整棵树会把补丁和统计作用到错误对象上。
- 几何名字通常就是 USD prim 路径，可能带有数字后缀用于区分重名网格。匹配碰撞体时要同时尝试去掉后缀。
- 改名必须同步更新所有引用，包括执行器、等式约束和接触排除，并检查重名。
- `<general>` 与 `<position>` 在参数满足位置伺服组合时完全等价，不要为了“好看”强行改写，否则会丢掉 USD 里的原始参数。
- 判断控制范围单位是否写错，可以用控制范围跨度与关节限位跨度的比值，接近 180/π 就说明写成了度。
- 判断一个几何是碰撞体还是视觉体时，优先看碰撞掩码，掩码为 0 时再看名字里是否带碰撞路径。

## 修改代码时的检查清单

1. 新的 USD 操作是否在解析之前执行。
2. 新的 MJCF 处理是否插在正确的顺序位置。
3. 新增配置项是否同时更新了配置定义、校验、说明、示例配置和文档。
4. 新增或修改的名字是否同步了引用。
5. 失败路径是否可见，是否会被悄悄跳过。
6. 统计信息是否写进了报告，方便以后排查。
7. 是否为新增逻辑补了单元测试。

## 测试与验证

- 单元测试全部在文本层运行，不需要 GPU 和外部资产。新逻辑优先写成可以用内存数据验证的纯函数。
- 涉及 USD 的逻辑可以创建内存中的 stage 来测试，不需要真实资产文件。
- 需要端到端验证时，找一份真实资产跑一次转换，然后检查报告里的统计和改动记录。
- 没有图形界面时不要用 MuJoCo 的交互式查看器，使用无头的编译、步进和离屏渲染。
- 报告是排查问题的第一入口，比日志更完整。

## 常见错误

| 现象 | 常见原因 |
|---|---|
| 改了 USD 属性但产物没变 | 修改发生在导入之后，或资产里的值优先 |
| 视觉几何颜色全部丢失 | 没有遍历实例代理，或材质采集发生在导入之后 |
| 模型没有任何接触 | 碰撞掩码为 0，或碰撞体被禁用后没有重新打开 |
| 模型形状比预期更“胖” | 碰撞网格被转成了凸包，凹形被填平 |
| 底面缺角 | 凸包顶点上限太小 |
| 关节一直顶住 | 控制范围单位写成了度 |
| 产物 XML 极大 | 网格没有外置 |
| 步进发散 | 时间步、阻尼和惯量的组合超出显式积分的稳定范围 |
