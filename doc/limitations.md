# 已知限制与排错

## 已知限制

### 写出接口不是完整往返

MJCF 的写出接口不导入传感器、相机、灯光、关键帧、复合体、蒙皮和插件。闭环约束只保留运动学耦合关系。关节速度上限会丢失。运动学根节点的 armature 会被改成一个很大的值。

需要这些内容时，用 `patch.add` 或 `patch` 的其他部分补回来。

### 碰撞体只能是凸的

MuJoCo 不支持凹的碰撞网格。工具会把碰撞网格转成凸包或凸块，因此凹形部位（例如杯状、镂空结构）的碰撞会变得比视觉模型更“实”。

如果 USD 里没有写近似方式，工具按凸包处理。视觉与碰撞的差异需要在使用时留意。

### 碰撞网格精度受资产限制

凸包顶点上限默认 64，可以用 `usd.max_hull_vertices` 提高。但提高上限只能让凸包更贴近 USD 里的碰撞网格；如果碰撞网格本身就是低精度模型，结果仍然不会更精确。

### 远程资产只跟随相对路径依赖

从网址加载资产时，工具会递归下载它引用到的文件。如果资产用绝对路径引用依赖，这部分无法自动映射，对应的配置组合会不可用。工具会明确列出缺失的文件。

### 运行时参数不在模型里

`nconmax`、`njmax`、`nvmax` 这类参数属于仿真运行时的缓冲设置，不是模型的一部分。它们不应该从 USD 的场景设置里照搬。

转换时使用的 MuJoCo 版本与训练环境可能不同。纯文本的 XML 可以跨版本读取，但仍建议在训练环境里重新编译一次。

## 排错

### 模型没有碰撞，直接穿过地面

按顺序检查：

1. 报告里的 `collisionMasks.fixed` 是否有内容。如果碰撞掩码全是 0，模型不会和任何东西碰撞。
2. 报告里的 `collision.mutedInUsd`。如果 USD 把碰撞体全部禁用，而 `usd.collision_mode` 是 `respect`，产物会没有碰撞。
3. 报告里的 `collision.selfMaterialFixed`。如果碰撞体自带材质信息且没有被修复，Newton 会跳过整个碰撞体。
4. USD 里是否真的有 `collisions` 目录。工具不会替 USD 补充碰撞几何。

### 模型落地后抖动或被弹开

常见的两个原因：

- 视觉模型和碰撞模型体积差异较大，或者碰撞体之间有初始重叠；
- 原本靠碰撞过滤避免的接触在重新打开碰撞体之后真实发生了。

处理方式是用 `mjcf.contact.excludes` 增加排除。MuJoCo 已经自动排除父子 body 对，只需要关心没有父子关系但互相重叠的部位。

### 底面看起来被切掉一角

碰撞网格的凸包顶点数不够。把 `usd.max_hull_vertices` 提高后再转换，并确认报告里的 `collision.hullOverrides` 命中了目标碰撞体。

### 关节不动，或者一直顶住

先检查执行器的控制范围。如果 USD 里把控制范围写成了“度”，而工具没有换算，控制范围会放大 57 倍，目标值会一直超出物理限位。

确认 `mjcf.fix_ctrlrange` 处于开启状态，并在报告里的 `ctrlrange.converted` 查看修了哪些执行器。

### 执行器没有名字

检查 `mjcf.actuator_names`。设为 `joint` 时，执行器会用所驱动的关节名命名。

### 名字太长或者重复

名字太长通常是因为 USD 里多个部件同名，工具必须加长路径才能区分。用 `patch.rename` 的正则改成喜欢的名字。

报告里的 `naming.unmatched` 列出的是 Newton 自己合成的名字，需要用 `patch.rename` 处理。

### 颜色不对或者材质发黑

- 确认 `mjcf.materials.enabled` 是 `true`；
- 资产使用高金属度材质时，MuJoCo 默认灯光下会发黑，这属于光照问题，不是材质丢失；
- 贴图文件缺失时，检查产物目录下的 `textures/`。

### 渲染失败或者图片是空的

- 无显示环境建议使用 `egl` 或 `osmesa`；
- 驱动或显卡不支持时可以把 `verify.render` 设为 `false`，不影响转换结果；
- 不要在没有显示环境的机器上使用 `simulate` 图形界面。

### 转换很慢或者显存不足

- 视觉网格很多时，可以先把 `mjcf.visuals` 设为 `false`；
- 没有 GPU 时把 `backend` 设为 `"cpu"`；
- 网格很大时，`mesh_mode` 保持默认的 `obj`，避免生成超大 XML。

### 提示 CUDA 或者驱动相关错误

转换默认使用 CUDA 后端，需要较新的 NVIDIA 驱动。无法升级驱动时，把 `backend` 设为 `"cpu"`。
