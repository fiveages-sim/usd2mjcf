# 开发指南

这篇文档面向修改代码的人，说明项目由哪些模块组成、一次转换经过哪些步骤、新增功能应该放在哪里。

## 目录结构

```
.
├── src/usd2mjcf/          转换器源码
├── scripts/               维护脚本
├── config/                示例配置（按机型分目录）
├── tests/                 单元测试
├── doc/                   项目文档
└── pyproject.toml         依赖与工具配置
```

## 模块职责

| 模块 | 职责 |
|---|---|
| `cli.py` | 命令行入口，解析三个位置参数，调用转换与验证 |
| `config.py` | 配置的数据结构、默认值、加载、保存、校验 |
| `convert.py` | 编排整个转换流程，产出结果对象和报告 |
| `usd_scene.py` | USD 侧的操作：打开 stage、选择变体、读写属性和材质、处理远程资产、采集名字表 |
| `materials.py` | 从 USD 解析材质与颜色，复制贴图 |
| `mjcf_edit.py` | 对生成的 MJCF 文本做后处理：场景设置、材质、掩码、视觉与碰撞分组、命名、网格外置、接触排除、补丁、标记点 |
| `verify.py` | 用 MuJoCo 编译产物，做步进和渲染检查 |

`convert.py` 是唯一的流程编排点。它按固定顺序调用上面的模块，任何一个新步骤都应该加在这里，而不是散落在各个模块里。

## 一次转换的顺序

1. 打开 stage；
2. 选择变体；
3. 修复碰撞体语义：自带材质的碰撞体、被禁用的碰撞体；
4. 设置凸包顶点上限；
5. 读取场景参数、材质和名字表；
6. 调用 Newton 解析 USD 并导出 MJCF；
7. 同步场景参数；
8. 应用材质；
9. 修复碰撞掩码；
10. 区分视觉体与碰撞体；
11. 修正执行器控制范围；
12. 还原名字并命名执行器；
13. 把网格写成独立文件；
14. 增加接触排除；
15. 应用补丁；
16. 补充标记点；
17. 写出文件，读取并验证产物。

前五步都在修改 USD 或读取 USD，必须在第 6 步之前完成。第 7 步之后都是对 MJCF 文本的处理，顺序同样重要，例如掩码修复必须在视觉与碰撞分组之前。

## 新增一个配置项

1. 在 `config.py` 对应的数据结构里增加字段，并在注释里说明作用、默认值和取值范围；
2. 如果取值有限制，在 `validate()` 里增加检查，并在 `describe()` 里增加一句说明；
3. 在 `convert.py` 或具体处理模块里使用这个配置；
4. 重新生成示例配置；
5. 更新文档中的配置参考。

示例配置由脚本根据数据结构生成，所以新增字段后必须重新运行脚本，否则测试会失败。

## 新增一个处理步骤

1. 在 `mjcf_edit.py` 或 `usd_scene.py` 中写一个独立函数，参数显式传入，返回值包含统计信息；
2. 在 `convert.py` 中按正确顺序调用它，把结果放进返回对象和报告；
3. 为它写单元测试；
4. 更新转换规则文档和报告字段说明。

处理步骤之间不要互相调用，通过 `convert.py` 串联，这样顺序变化时容易审查。

## 测试

测试全部在文本层运行，不需要 GPU 和 USD 资产。运行方式：

```bash
uv run pytest
```

| 测试文件 | 覆盖内容 |
|---|---|
| `test_config_examples.py` | 示例配置可加载、没有未知键、示例文件与配置定义一致 |
| `test_mjcf_edit.py` | 补丁、重命名、元素匹配、XML 读写 |
| `test_collision_masks.py` | 碰撞掩码修复 |
| `test_contact_excludes.py` | 接触排除的匹配与去重 |
| `test_ctrlrange.py` | 控制范围单位换算与补齐 |
| `test_sites.py` | 标记点写入 |
| `test_visual_collision_split.py` | 视觉体与碰撞体的分组 |
| `test_max_hull_vertices.py` | 凸包顶点上限的覆盖 |

测试需要 USD 运行时的地方使用内存中的数据，不依赖外部资产文件。

## 脚本

`scripts/write_example_config.py` 读取配置定义，生成 `config/config.example.json`。修改配置结构后必须重新运行它。

## 依赖约束

- 依赖通过 `uv` 管理，新增依赖时同步更新 `pyproject.toml` 和锁文件；
- Newton 的网格近似功能依赖 `scipy`、`trimesh` 和 `coacd`，缺少这些依赖时凸包会直接退化成包围盒，而且不会有明显提示，因此依赖里固定带上这些包；
- MuJoCo 与 `mujoco-warp` 的版本需要保持一致，便于验证和训练使用同一套行为。

## 代码风格

- 每个文件开头用一段中文说明文件职责；
- 每个类、函数和方法都有中文说明，写清楚目的、参数含义和副作用；
- 处理 USD 或 XML 的函数尽量保持无状态，便于单独测试；
- 功能通过配置项和独立的处理函数扩展，避免在一个函数里堆叠条件分支。
