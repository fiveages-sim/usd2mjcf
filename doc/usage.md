# 使用指南

## 这个工具做什么

`usd2mjcf` 把一个 OpenUSD 物理资产转换成 MuJoCo 的 MJCF 文件。

转换结果是一个自包含的模型：普通的 pip 版 MuJoCo、`mujoco-warp` 或 mjlab 都能直接加载，不需要安装 USD 相关组件。USD 里已经写好的控制器参数、关节参数、场景参数会尽量原样保留，因此通常不需要在 MuJoCo 一侧重新调参。

## 环境准备

需要的运行环境：

- Python 3.12；
- 用 `uv` 安装依赖（仓库里已经有 `uv.lock`）；
- 默认使用 CUDA 后端做转换，需要较新的 NVIDIA 驱动。没有 GPU 时，把配置里的 `backend` 改成 `"cpu"`。

首次安装依赖：

```bash
uv sync
```

## 运行一次转换

命令行只有三个位置参数：

```bash
uv run usd2mjcf <输入.usda> [输出.xml] [配置.json]
```

例如：

```bash
uv run usd2mjcf ~/project/assets/robot.usda ~/project/out/robot.xml
```

几个约定：

- 省略输出路径时，会在当前目录生成与输入同名的 `.xml`；
- 省略配置路径时，全部使用默认配置；
- 第二个位置参数以 `.json` 结尾时，会被当作配置文件；
- 也可以使用 `-o/--output` 和 `-c/--config` 显式指定输出与配置；
- 输入可以是文件、目录，也可以是 `https://` 开头的网址。

第一次转换建议不带配置，先看生成的报告，再把需要覆盖的项写进自己的配置。

目录输入时会自动挑选入口文件，并打印候选文件的排序结果。网址输入时，工具会先把资产和它依赖的文件下载到本地缓存（默认是当前目录下的 `.usd_cache`），下次直接复用。

## 产物

转换完成后，输出路径旁边会出现这些东西：

| 产物 | 说明 |
|---|---|
| `robot.xml` | MJCF 模型，可直接加载 |
| `robot.report.json` | 转换报告，记录本次所有判断和改动 |
| `robot_view0.png`、`robot_view1.png` 等 | 验证时离屏渲染的图片 |
| `meshes/*.obj` | 外置的网格文件 |
| `textures/*` | USD 材质带贴图时复制出来的图片 |

报告是最有用的排查入口，里面包含：

- 每个变体集合的全部候选值、本次选中的值和选择原因；
- 场景参数的实际取值和来源（来自 USD 还是配置）；
- 被 USD 禁用、随后被重新打开的碰撞体路径；
- 视觉体与碰撞体的数量；
- 材质、网格、执行器的统计；
- 命名结果和未能匹配的名字；
- 本次实际生效的完整配置。

## 自动验证

转换结束后，工具会用不带 USD 支持的 pip 版 MuJoCo 做一次校验：

1. 编译模型，确认文件可以被正常加载；
2. 打印关节、自由度、几何、网格、接触排除等统计；
3. 检查积分器参数是否会导致数值发散；
4. 空控制步进若干步，检查是否出现 NaN 或异常速度；
5. 离屏渲染几个视角。

验证不通过时命令的退出码非零。如果当前环境不需要验证，可以在配置里关闭：

```json
{
  "verify": {
    "enabled": false
  }
}
```

如果只需要关闭渲染，保留步进检查：

```json
{
  "verify": {
    "render": false
  }
}
```

在容器或 CI 里运行时，不要用 `simulate` 图形界面检查模型，使用上面这套无头验证即可。

## 常用操作

| 想做的事 | 改哪里 |
|---|---|
| 换底盘、机械臂、末端执行器等可选配置 | `usd.variants` |
| 提高碰撞网格的凸包精度 | `usd.max_hull_vertices` |
| 重新打开被资产禁用的碰撞体 | `usd.collision_mode` |
| 把网格写成单独文件或塞进 XML | `mjcf.mesh_mode` |
| 调整名字 | `mjcf.name_from_usd` 和 `patch.rename` |
| 修正执行器控制范围 | `mjcf.fix_ctrlrange` 等 |
| 补充 TCP、相机等标记点 | `mjcf.sites` |
| 增加额外碰撞排除 | `mjcf.contact.excludes` |
| 临时改写执行器参数 | `patch` |

每个配置项的详细说明见[配置参考](configuration.md)，转换规则见[转换规则](conversion.md)。

## 在训练框架中使用

生成的 XML 是普通 MJCF，直接加载即可。需要注意：

- `nconmax`、`njmax`、`nvmax` 这类参数是运行时缓冲，不属于模型，不要从 USD 的场景设置里照搬；
- 不同 MuJoCo 版本对 MJCF 的接受范围略有差异，转换时使用的版本和训练环境不一致时，建议在训练环境里再编译一次；
- 模型里可能包含用于展示的视觉网格，只训练不需要渲染时可以在配置里关闭 `mjcf.visuals`。

## 遇到问题

先看[已知限制与排错](limitations.md)。如果问题属于资产本身（例如 USD 里没有碰撞几何、贴图文件缺失），转换工具不会凭空补出来，需要回到资产制作环节处理。
